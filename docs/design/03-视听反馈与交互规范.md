# 03 · 视听反馈与交互规范

本篇说明如何把规则表达给玩家；行为定义以[核心玩法](01-核心玩法与战斗规则.md)为准，验收证据以[工作流](../ai-workflow/03-开发工作流与验收.md#4-验证与交付判定)为准。已有美术资源仍需检查尺寸、动画、材质和音频是否适合具体玩法。

<a id="des-present-01"></a>

## 1. 目标与状态可读（DES-PRESENT-01）

玩家需要辨识目标是什么、何时危险、如何应对。轮廓、亮度、材质、颜色、动作和标记共同表达，按背景和任务选择有效的组合。敌人、禁射对象、机关和弱点采用一致语言，重要区别不能只靠颜色。

可读性检查覆盖实际画幅、目标大小、运动、背景、遮挡与特效。几何上在画面内不等于玩家能识别，完整模型可见也不等于关键弱点可见。首阶段按像素和屏幕占比标定；未来真实光枪的屏幕尺寸、站距和追踪状态需另行评估。

题材风格由规格决定。暗场、滤镜和写实材质可使用，但须保持已声明应对的可辨识性，并检查实际资源装配与性能成本。

<a id="des-present-02"></a>

## 2. 反馈事件与表现层（DES-PRESENT-02）

表现订阅结果事件，按开火、空仓、命中、被挡、打断、击杀、受伤和装填完成选择反馈包。声音、部位动作、准星标记和特效可组合使用，关键结果需要清楚区分。

例如护盾挡住子弹应区别于有效伤害；缴械后逃离应区别于击杀。表现需要告诉玩家“发生了什么”，而非给所有情况同样强的闪白和浮字。题材决定音色和视觉尺度，不强制血浆、断肢或屏幕震动。

规则结果、动画事件与反馈时点保持可检查的对应关系。记录输入、判定和表现时间，实测延迟；不写零帧命中、统一顿帧或反馈结束时长。命中确认不可依赖下一次开火才更新。

镜头震动、慢镜和顿帧按需使用，启用时定义对游戏计时和操作的影响。优先让瞄准保持稳定；若效果显著影响攻击窗口，按规则验证。物理后坐力以后通过事件适配，不进入首阶段验收。

<a id="des-present-03"></a>

## 3. 音频与信息优先级（DES-PRESENT-03）

音频承担开火结果、状态确认、威胁提示和氛围。枪声、命中声、空仓和重要敌人提示能够区分，音色和音量以实际混音中的辨识效果为准。

同时事件多时限制重复播报、并发数量和优先级，让关键提示不被音乐与爆炸盖住。按需要让背景音乐让位，并检查并发战斗事件下的效果。

不能只靠方位音或台词承载必需应对；静音、单声道或未听清台词时应有可辨识的视觉状态。声音可补充屏幕外预告，但不能使仍未提供可执行应对的攻击自动变公平。

配音、本地化和演示循环按项目语言及内容需求选择，不默认强制配音、口头禅数量或传播片段。字幕覆盖剧情与必要信息，关键提示在战斗中仍需可读。

<a id="des-present-04"></a>

## 4. HUD、准星与布局（DES-PRESENT-04）

HUD 优先回答当前能否开火、弹药/生命状态和任务信息；计分启用后再显示相关信息。按信息量选择图标、数字或混合表达，验证实际游玩尺寸下的读取效果。

每位活跃玩家显示独立准星，使用玩家编号、形状与颜色共同区分；准星重叠时仍能辨识各自位置。系统光标的显示归菜单/输入上下文管理，避免与游戏准星重复造成误判。准星尺寸、颜色与状态标记可以调整，不能遮住必须精确命中的目标。目标预警与准星分别表达敌人状态和玩家输入。

布局避开主要射击区域，允许任务提示在中心短暂出现，但不能遮住同时需要处理的目标。生命、弹药、任务与结算使用相同单位和含义，扣分与失败原因可追溯。低血量或空仓可以加强提示，避免长时间闪烁和重复播报遮盖威胁。

双人 HUD 分别显示生命、弹药、失能和装填状态，公共任务单独显示。攻击预警标明受威胁玩家或全队，个人命中反馈带归属；声音播报明确对象，避免 P1 空仓使 P2 误以为自己不能开火。双人准星、浮字与特效叠加后的可读性和性能需要单独检查。

黑边、画幅和缩放后，HUD、点击区域与准星仍在正确内容区域。安全边距由显示和输入配置确定，不固定为画面比例。真实边框识别光枪以后按具体设备验证其占用区域与画面限制。

<a id="des-present-05"></a>

## 5. 菜单、暂停与舒适设置（DES-PRESENT-05）

开始、暂停、重试、设置和退出使用清楚的鼠标交互。按钮的可点区域与显示位置一致，首次游玩可看到控制方式。必要键位可映射，设置更改后明确何时生效。

普通暂停冻结战斗、装填、镜头和游戏计时，遵循架构的统一时钟。恢复时不把菜单点击传给战斗；需要倒计时或恢复宽限时写入规格并同步危险时钟，不能只锁住玩家输入却让敌人继续攻击。

按需要提供 UI 缩放、准星调整、字幕、减少镜头运动和闪烁等选项。静音或关闭震动后仍有关键状态表达；不要求玩家必须接外设才能获得命中确认。舒适设置改变游戏节奏时，检查与计分模式的关系。

<a id="des-present-06"></a>

## 6. 资源装配与证据（DES-PRESENT-06）

正式资源装配后重新检查骨骼动作、弱点随动画的位置、透明材质、音效、HUD 和装饰遮挡。特效、尸体与音频并发数量按平台预算限制，清理不得让仍然有效的威胁突然不可见。

视听记录关联关卡、事件和构建版本，截取危险窗口及反馈片段；静态截图不能验证声音和时序。具体采集与四层验证由工作流实现。

<a id="des-present-07"></a>

## 7. 美术风格如何影响游戏性（DES-PRESENT-07）

**规则参数不变，实际玩法难度也可能变化。** 下面是本项目需验证的设计推论，影响取决于具体资源和画面，不是对某种风格的固定评价。

- **识别与优先级**：轮廓、明暗、纹理密度和特效影响目标/禁射对象/攻击状态的辨识。写实的细节与相近材质可能掩盖弱点；卡通或低模的清楚轮廓也可能因同色背景与密集描边而混叠。识别变慢会压缩实际应对余量。
- **瞄准与命中**：比例、部位尺寸、姿态、运动与透视影响可瞄准面积。夸张大头可能让爆头更容易，细小手臂可能使缴械更难；复古像素化或抖色可能隐藏小部位。可见轮廓与实际命中区域需一致，不能悄悄扩大碰撞来掩盖美术问题。
- **状态与节奏**：动作前摇、弱点发光、护盾形态和倒地方式决定玩家何时认为能攻击、何时认为目标已处理。卡通拉伸或写实微动作需要不同表达；暗场、烟雾与惊吓可以增加压力，但普通危险仍须满足已声明的应对窗口。
- **情绪与行为理解**：题材、造型与反馈强度可能影响紧张感、射击意愿、对友军和可破坏物的判断。因此要检查玩家是否理解交互语义，并按参考片段或试玩评价节奏；不把这种主观影响换算成未经标定的难度系数。
- **双人合作**：两路准星、提示、命中与 VFX 会共同占用画面。风格配置要保留玩家身份与敌人状态两套语言，并在争抢目标、跨区射击和同时爆炸时保持可读。
- **运行表现**：材质、光照、透明效果、骨骼和后处理影响实机负载。低模不自动等于低成本，透明层与屏幕覆盖率也需检查；实时帧时间变化是否破坏瞄准与反馈以设备测量为准。[Godot GPU 优化说明](https://docs.godotengine.org/en/stable/tutorials/performance/gpu_optimization.html)

关键视觉信息与背景的对比需在变化场景中持续检查，可用轮廓或可配置对比增强；UI 和提示的具体做法参考 [Xbox 对比度指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)。不将 UI 对比度标准直接当成所有动态 3D 模型的通用通过阈值。

### 风格配置与标定

GameSpec 引用一个版本化的风格配置：参考画面、轮廓与弱点表达、敌人/禁射对象/玩家标记、动画提示、光照/背景/后处理限制、目标投影范围、特效并发限制及平台画质。它是现有规格的一部分，不增加第五类核心数据。标签和数值只是声明，实际片段与测量证明其适用范围。

先用少量正式资源做代表性战斗小场景，标定识别和瞄准目标，再用这些约束生成关卡。检查单人/双人、实际画幅、各平台画质下的状态区分、部位可射击、应对余量和帧时间；AI 图像评价是线索，需与事件、投影、录音和试玩证据互证。

更换风格时区分两类变化：

- 保持几何、碰撞与行为时序，仅改材质、灯光或后处理：逻辑契约可保持，视听与平台检查必须重跑，带识别/瞄准误差的压力评价重新标定。
- 改模型比例、弱点、碰撞、动画时序或建筑空间：属于功能相关变化，连同取景、事件窗口和受影响行为/关卡回归一起检查。需要改硬规则时先修订规格。

对比时保留相同的基础关卡、输入与摄像机记录，比较实际画面和性能；必要时再用重新标定的玩家能力模型检查压力。固定输入回放可以定位差异，不能模拟真人看到新风格后重新作出的判断。只有本次选用的资源风格需要验收，不强制每次游戏覆盖所有风格。

## 8. Review 重点

- 玩家能否区分有效命中、被挡、打断和击杀？表现与实际状态是否一致？
- 动画、装饰、HUD 和特效是否遮挡弱点或提示？关闭声音或舒适效果后是否仍可理解？
- 缩放、黑边和画幅变化后，准星、按钮和目标是否对齐？
- 截图、片段和录音是否来自当前构建？是否把临时资源表现当成最终验收？
- 是否把风格当成纯贴图替换？双人叠加、风格/画质变化后的难度与证据是否重新检查？
