# 01 · 核心玩法与战斗规则

本篇把机制描述转为可实现、可验证的行为。规则分类与使用方法见[总入口](../README.md#3-方法与规则的使用方式)；镜头编排见[关卡方法](02-关卡节奏与内容结构.md)，反馈表达见[视听规范](03-视听反馈与交互规范.md)。这是设计依据，具体参数写入每次 GameSpec。

<a id="des-combat-01"></a>

## 1. 核心决策与输入（DES-COMBAT-01）

定轨射击由系统控制移动和镜头，玩家主要决定瞄准对象、开火时机、处理顺序；装填、掩体、切换武器等可以增加决策。新增动作需说明决策价值、输入方式与教学成本。

起步采用屏内鼠标模拟瞄准与开火、可映射按键装填和暂停，每位玩家独立绑定输入与武器状态。菜单也可使用鼠标。装填未启用时去掉该动作与弹匣压力；输入数量以能清楚教学和实际操作为准。双人是基线，具体合作规则见第 7 节；鼠标模拟不代表已验证真实光枪。

每个动作定义何时有效、重复或持续输入如何处理、无效时有什么反馈。菜单确认与战斗开火分上下文，确认“开始”不能顺带打一枪。指针超出有效画面时不产生边缘射击，也不自动推断为离屏装填。

<a id="des-combat-02"></a>

## 2. 武器、资源与命中（DES-COMBAT-02）

基础行为必须回答：单击还是持续射击；射速限制；弹药是否有限；空仓、装填中和暂停时能否开火；装填能否中断、是否耗储备；完成时补多少弹。以弹匣和储备分开记账，定义容量与上下限，避免重复完成事件重复补弹。

准星、射线和可射击部位遵循同一坐标与时间约定，技术口径以[架构第 5 节](../ai-workflow/01-系统架构与数据契约.md#5-时间与判定的一致性)为准。规格声明普通部位、弱点、护盾、穿透和爆炸规则；模型外观、碰撞和伤害部位必须一致，允许的辅助命中范围需要明示并验证。

开火成功、空仓、命中、被挡、打断和击杀是不同结果，表现分别表达这些状态。伤害与奖励基于结果事件，不能依据粒子或动画播放次数结算。

弹药、拾取、武器切换和成长都是可选设计：

- 装填压力由安全时机、持续威胁和任务计时共同形成；检查有限弹药下是否存在完成路径。
- 武器变化应改变可感知的取舍，例如高伤害低射速、范围伤害与误伤风险。没有决策价值时优先减少切换。
- 拾取定义射击拾取、自动领取或其它方式，以及容量已满、过期和重试时的处理。
- 成长可改变伤害、容量、装填或能力，但每档都需重新验证窗口与压力。计分比较口径见第 6 节。
- 可破坏环境明确对象、触发条件和结果，资源目录登记对应能力。

<a id="des-combat-03"></a>

## 3. 敌人、威胁与应对（DES-COMBAT-03）

每种敌人先定义玩法职能，再绑定模型：例如迫近目标考验瞄准速度，远程攻击考验优先级，护盾考验应对选择，投掷物考验转移注意力。职能不绑定固定题材、敌人数或出场顺序。

危险攻击定义“提示→可执行应对→危险生效→恢复/结束”。提示应能在目标画面中辨识，应对可以是击杀、打断、打弱点、击落飞行物、掩体或其它选定动作。不能将“所有危险都必须能直接射杀”作为基线；无解的扣血事件也不能冒充正常可应对攻击。刻意设计的不可避免损失或风险选择须作为例外写入规格，并让玩家理解后果。

应对窗口要考虑识别、转移瞄准、必要射击次数、射速、弹药与装填，并按整波检查同时威胁；计算方法见[生成方法第 6 节](../ai-workflow/02-场景与关卡生成方法.md#6-可见性可应对窗口和压力)。不使用统一的“生理反应下限”。

敌人契约至少包含：可射击部位、生命/抗性、状态、攻击时点、可打断状态、硬直与重复限制、死亡或离场后的攻击处理。普通命中、打断、缴械、死亡不自动等价。霸体或无敌时须有状态表达；若无限打断是允许策略应明示，否则定义限制并验证。

BOSS 按需采用阶段、弱点、机关或多目标结构。每阶段明确可伤害时段、攻击与应对、转换条件和结束结果。固定规律可以便于学习，变化可以增加压力；两者都需可读、可复现。弱点运动和阶段位置根据具体遭遇选择。

<a id="des-combat-04"></a>

## 4. 任务、胜败与重试（DES-COMBAT-04）

任务完成条件独立于“清空敌人”：可以击杀指定对象、坚持到时限、救援、击破机关或选择路线。每个必需对象明确哪些终态算完成，哪些导致失败，哪些只是后果。例如敌人逃离不能一律当成清场。

可选救援要定义成功、超时、误伤、救援对象死亡和奖励规则，并区别于可攻击目标。掩体要定义进出、可否开火、是否免伤、是否装填，以及任务计时是否继续；免伤和计时不能由表现层自行决定。

首版重试边界为驻点起点：明确重建该点的弹药、生命、敌人、任务、随机状态和可选计分。区分驻点初始快照与全新会话，不默认重试恢复满血满弹。上次尝试的弹道、输入和回调不得影响新尝试。更细保存粒度以后按需求扩展。

<a id="des-combat-05"></a>

## 5. 难度与调参（DES-COMBAT-05）

难度来自任务组合、可用时间、目标位置与运动、攻击重叠、命中要求、资源供给和参与人数。美术的轮廓、动作与背景还会改变识别和瞄准耗时，须按 [DES-PRESENT-07](03-视听反馈与交互规范.md#des-present-07) 标定。先定位失败原因，再调整相关参数；没有适用于所有游戏的旋钮优先级。

先用规则机器人筛查明显无解、卡死和资源不足，再用带明确反应/误差参数的机器人检查压力，最后评价实际画面与试玩。机器人通关不能证明新手觉得公平，也不能用完美机器人的表现决定默认难度。

记录失败驻点、攻击类型、弹药、命中率、应对剩余时间和重试情况。与规格中的目标玩家、难度档和体验目标比较；不预设统一通关率或死亡次数。调整前后保留同组回放，防止改一处后造成其它规则失效。

动态难度为可选机制。启用时锁定可调参数、范围、触发依据与生效边界，记录实际调整；不得隐式改变命中部位、伤害或胜败语义。计时、成长和动态难度参与排名时，比较口径须明确。

<a id="des-combat-06"></a>

## 6. 计分与比较口径（DES-COMBAT-06）

计分可用于反馈、练习或竞争，第一阶段不要求排行榜。启用时定义得分事件、扣分、倍率、连击中断与结算规则，保证同一结果只计一次；击杀浮字与结算分项应可核对。连击可以按时间、命中连续性或其它规则设计，不能几处脚本各自判断。

不同版本、难度、路线、装备或随机配置不自动具有可比性。竞争模式选择固定条件或分组比较，并保存配置。随机性可以保留，但应能说明它对成绩的影响。

启用双人计分时，默认团队得分，并分别记录个人有效命中、伤害和协作贡献。每次击杀/任务奖励只入账一次；个人竞争计分按规格另设归属规则。双人、单人及不同风格/画质下的成绩是否可比较需要明确，不能因为规则参数相同就自动合榜。

<a id="des-combat-07"></a>

## 7. 双人合作基线（DES-COMBAT-07）

本项目标配本地双人共享屏合作，同时保留单人模式；默认共同镜头、共同任务与敌人生命池。每位玩家有独立瞄准、开火、装填、弹药、生命和状态，友军误伤默认关闭。用户可改共享资源、失败方式和合作机制，但双人能力不能在生产时被当作可选项略过。

- **伤害与归属**：开火和结果携带玩家身份，共享目标统一结算。两人同时射击可以共同造成伤害，但击杀、机关完成和任务奖励只发生一次。同一结算批次内的过量命中单独记录，默认不重复奖励，也不作为瞄准失误惩罚。批次与事件顺序由架构定义。
- **攻击目标**：攻击声明影响 P1、P2 或全队，提示与实际扣血一致。默认攻击一个玩家时只扣该玩家生命；针对两人的攻击分别检查应对，不能因一人已进入掩体就认为另一人安全。
- **失能与重试**：默认一人失能后另一人可以继续，双方均失能才触发战斗失败；任务失败仍可导致全队失败。失能玩家不再执行战斗动作。首版在下个驻点按规格恢复其参与状态，驻点重试同时恢复双方与世界的起点状态；复活资源需与关卡压力共同标定。
- **加入退出**：首版在开始或驻点边界选定参与人数，当前交战不无声改变人数。输入设备断开时全局暂停并提供重连；确认转单人时从当前驻点起点按新人数重新初始化。交战中直接加入、救起队友或无缝退出属于以后可扩展规则。
- **合作决策**：模板支持分区处理、优先目标、错峰装填或互补任务；双人组合应允许两人贡献，并检查抢靶、重复处理和长期一人无事可做。硬性要求两人同时完成的机关需提供单人替代规则，或只用于明确的双人专属内容；还须明确一人失能时的替代、恢复或任务失败结果，不能一直等待无法再执行的动作。

双人压力通过人数配置与编排验证，不默认把敌人数或生命简单乘二。自动试玩覆盖协同分工、争抢同一目标、能力不对称、一人装填/失能等情况；两路完美机器人不能代表真实合作体验。实际双人输入的能力与证据见架构和工作流，联网、多枪实体设备与串流不由双人标配自动纳入范围。

## 8. Review 重点

- 玩家每个动作的有效状态和反馈是否清楚？武器、敌人、任务有没有互相矛盾的规则？
- 每个危险是否有已声明且可执行的应对？整波是否仍有完成路径？
- 击中、打断、缴械、离场和死亡是否区分？胜败与奖励能否重复触发？
- 可选机制是否由规格选用？重试、难度和计分比较口径是否明确？
- 双方能否独立操作且参与同一任务？同时命中、攻击归属、失能和人数变化是否明确？
