# 02 · 关卡节奏与内容结构

本篇定义交战和内容编排方法；程序化实现见[生成方法](../ai-workflow/02-场景与关卡生成方法.md)。战斗行为以[核心玩法](01-核心玩法与战斗规则.md)为准，不在这里再定义伤害、装填和任务终态。

<a id="des-level-01"></a>

## 1. 从描述提取体验目标（DES-LEVEL-01）

描述先回答：玩家在做什么任务；主要面对什么选择；希望获得什么感受；有多少内容；结束与重试如何发生。例如“废弃工厂救援，先处理即将开火的敌人，再准确救人”比“做一个紧张刺激的游戏”更能驱动生成。

题材提供空间、美术和叙事约束，机制仍由用户需求决定。例如恐怖可以靠未知与声画铺垫，军警可以选择救援或其它任务。资源风格、反馈尺度与任务表达在规格中一起确定，避免题材与玩家看到的结果冲突。

第一阶段采用定轨驻点形态。固定镜头靶场适合局部验证；持续移动交战、自由走位或多屏切换需要不同模板和验证，后续根据描述扩展。关卡时长、章节数、故事篇幅不是品类硬约束。

<a id="des-level-02"></a>

## 2. 驻点与关卡骨架（DES-LEVEL-02）

推荐结构为“关卡→驻点及连接→波次/任务→敌人/机关”，小关可以只有一个驻点。每点定义：

- **作用**：教学、练习、组合压力、恢复或高潮，可兼具多种作用。
- **内容**：玩家处理什么，从哪里出现，有什么应对。
- **取景**：镜头与目标的空间关系、关键可见区域。
- **结果**：怎样完成或失败，结束后去哪里，重试从哪里开始。

先安排教学与难度变化，再选建筑与模型。不能把模块随机拼接后出现的敌人数当成关卡设计。空间和取景共同约束遭遇，正式生成通过几何检查决定候选能否成立。

取景和压力同时受实际美术与人数影响：手臂较细、背景较繁杂或前摇动作较隐蔽的资源，可能需要更近取景、更清楚的提示或更低的同时威胁；两人共享镜头时要检查双方任务目标在同一画面中可理解。依据见 [风格与玩法](03-视听反馈与交互规范.md#des-present-07)，不凭风格标签直接套用难度倍率。

第一版使用无循环驻点图。后续如果加入返回、追逐或循环任务，必须同时补上结束条件、状态持久性和回放验证。

<a id="des-level-03"></a>

## 3. 镜头与战斗协同（DES-LEVEL-03）

基本节奏是移动、落位确认、交战/任务、结果处理、下一点或结束。它对应工程导演的阶段，不额外建立一套计时状态。

落位确认让玩家理解新构图；具体长度按画面和试玩确定。可以提前做入场演出，但危险生效须满足该驻点的提示和应对约定，演出事件与交战时间轴分别声明。

运镜服务于取景、空间理解、叙事与节奏。位置和朝向分别设计，减少突然转向；交战时优先保持关键目标可追踪。镜头抖动、快速切换或持续运动被选作玩法时，必须把其对瞄准与可读窗口的影响纳入验证。

连接段可以预告威胁、展示路线、恢复注意力或演出。记录等待原因和预计时长，观察是否破坏体验。可跳过演出须定义跳过后状态与计时，不能丢失必需任务事件。

<a id="des-level-04"></a>

## 4. 波次、压力与模板（DES-LEVEL-04）

一波不仅是敌人列表，还包含开始条件、入场顺序、攻击安排、资源供给和完成条件。后波可以依赖前波结束，也可以定时进入；重叠需要验证，不能因为玩家慢就自动堆到无法应对。

常用编排是先单独教规则，再练习，再与已有威胁组合，最后收尾或恢复。它是默认建议，不要求每个驻点重复完整序列。威胁数量、目标尺寸和同时攻击应共同决定压力，远距离小目标与近距离大目标不能只比较敌人数。

模板记录“决策、资源能力、风格约束、空间约束、人数配置、参数范围、完成规则、验证用例”，而不是一张固定刷怪表。例如：

- **单目标教学**：让玩家辨识提示和命中结果；需要清楚取景。
- **威胁排序**：不同方向或不同时限的目标，要求选择处理顺序。
- **装填压力**：在有限弹匣与安全时机之间决策；仅用于启用装填的规格。
- **状态窗口**：护盾、探头或弱点开放，要求识别何时可攻击。
- **事件任务**：按需加入救援、机关或分支，并明确结果处理。
- **双人协作**：分区处理、错峰装填或互补目标，并声明单人替代规则，避免一人失能后必然卡关。

更换资源、入口、空间深度和事件组合可以产生变化；所有变化仍须满足所选战斗规则。只换模型与随机位置不能证明生成了新的关卡体验。

所有普通模板都要覆盖单人和双人配置；双人专属任务显式标注。双人波次检查双方的任务机会、威胁归属、争抢同一目标和资源分配；先改变任务组合与攻击编排，再按测量调整数量和生命。不把两份单人刷怪表叠加视为完整双人设计。

<a id="des-level-05"></a>

## 5. 分支、重试与内容规模（DES-LEVEL-05）

分支是可选内容。启用时定义触发、选择期限、默认路线、分支后果和汇合方式。可以由玩家选择或任务结果触发，但结果须可理解，例如门被打开、救援成功改变路线。

差异可以来自任务、敌人组合、取景、奖励或叙事，不要求每条路整体换一套资产。避免增加大量路线却没有可感知变化；每条新支路都增加生成、失败路径和平台验证成本。

驻点起点是第一版重试边界，状态恢复遵循 `DES-COMBAT-04`。节奏设计要考虑失败后的重复负担，尤其是不能跳过的连接段，按试玩结果调整恢复节奏。

内容规模写成实际交付清单：驻点、遭遇、独有任务、路线和复用模板。用完整回放测量一次成功流程、含重试流程以及不同路线的耗时，分别报告。不将“难度档×分支×模式”的乘积直接换算为游玩小时数，也不以承诺 UGC 或后续更新弥补当前内容不足。

<a id="des-level-06"></a>

## 6. 设计如何进入自动生产（DES-LEVEL-06）

AI 为每个驻点给出所选模板、设计作用、需求/规则引用、单/双人人数配置、所用风格配置、完成条件和预计压力，再生成具体空间与事件。设计作用是规划依据；运行时需要的状态与条件才进入 LevelIR。

先灰盒验证任务与取景，再装正式资源，最后装饰。不能依赖临时方块的清晰轮廓推断正式美术也可读。生成与修复必须保持任务和规则，无法容纳遭遇时更换空间或调整允许参数；不能静默删除关键机制。

生成步骤、时间窗口、随机复现和预算检查以工程文档为准。本篇不另设一套生成命令、数据字段或通过标准。

## 7. Review 重点

- 各驻点有什么设计作用和决策？镜头、波次和任务是否相互支持？
- 变化是否产生可感知差异，还是只增加路线和模型数量？
- 分支、推进和失败后的重试是否完整？连接段或演出是否造成重复负担？
- 内容清单和耗时是否来自实际流程，是否把排列组合当作内容价值？
- 正式美术是否改变取景与应对耗时？双人时是否都有决策机会，失能或转单人后是否仍有完成路径？
