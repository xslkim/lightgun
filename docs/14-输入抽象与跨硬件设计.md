# 14 · 输入抽象与跨硬件设计

> 本章是全库的工程前提章。光枪品类史上硬件三次断代——CRT 光栅感应→红外参考点→摄像头屏幕追踪——每一次换代都作废了当时的全部存量外设，其中两次几乎带走整个品类（铁律 3，`00` §2）。因此光枪游戏的设计必须活在**输入抽象层**上：针对"一支输出绝对坐标的指向设备"设计，而不是针对任何具体硬件。本章把全库工程约束升维为硬件无关的设计要求；具体厂商方案（Sinden 边框、Gun4IR 红外、Retro Shooter 后坐力等）只作为证据出现，不是处方。

## 1. 输入抽象契约（全库的工程前提）

现代光枪外设大多以标准指针设备形态对游戏呈现——这让原生支持的工程成本很低；但**多人定位与输入配对必须由游戏自己实现**。游戏面对的从来不是"某支枪"，而是满足以下契约的抽象设备，**每条契约同时是对游戏输入层的设计要求**：

| 契约 | 内容 | 支撑的设计 |
|---|---|---|
| **每枪一条独立绝对坐标流** | 多枪时每支枪必须是独立坐标流，不得依赖运行环境的单一光标抽象（多数桌面系统只有一个合并光标，两支枪裸用会互相争抢） | 双人多枪（`11`）、Point Blank 式 4P |
| **坐标与扳机按设备配对** | 扳机/按键事件可按设备区分，且与该设备的坐标流同源（社区工具 DemulShooter 长期以此路线支撑多枪，证明可行） | 开枪认领（`06` §5）、命中归属（`11` §2） |
| **热插拔** | 按设备枚举（不按接口顺序硬编码），任意时刻插拔可恢复 | 双人 drop-in（`11` §4） |
| **更新率与帧率解耦** | 位置流更新率（常见约 60Hz）可低于游戏帧率——高帧率下准星隔帧重复是正常现象而非卡顿；可选准星外推，默认关（外推伤 1:1 信任） | 手感管线（`06` §4） |
| **无专用 API 兜底** | 拿不到分设备坐标时，按设备对事件流逐条积分重建绝对坐标；注意"边缘钳制漂移"（枪顶在屏幕边缘时仍持续产生增量，需钳边补偿） | 无厂商 API 设备的多人兜底 |
| **离屏状态可表达** | 枪口离开有效画面必须可被识别（坐标出界，或设备注入离屏事件） | 离屏装填（`06` §2.4） |

验收口径：任何符合契约的设备——今天的或未来世代的——接入后都应"零配置、开枪即中"。

## 2. 从技术约束到设计规则（硬件无关版）

硬件流派会换代，但当代屏幕追踪派（摄像头读屏）与红外参考点派（外置灯条）的设计约束交集稳定：**绝对定位 + HUD 安全区 + 快速软校准**——按交集设计即可同时兼容两派与未来硬件。以下规则全部通用：

1. **HUD 安全区**（屏幕追踪类共性约束：识别边框会压缩画面外围，证据：Sinden/RS3 边框叠层）：四边内缩 max(边框宽+4px, 画面高 5%)，用户可调（`13` §5）；四角不放点击目标；禁长时全白（冲掉边框对比度）与曝光突变转场（全黑拉高相机增益致边框过曝光晕）——惊吓转场改快速暗切/遮罩收缩（`03` §3.3）；可提供游戏内自绘识别边框选项（宽度可调），摆脱对设备端叠层软件的依赖。
2. **绝对定位一等公民**：光标即准星；**准星渲染开关**（默认开；街机模式关准星+可选盲打加分——Gun4IR 用户群的"街机原教旨"证明高精度设备需要它）；渲染准星时防止系统光标与游戏准星双光标并存（隐藏系统光标并约束在目标显示区域内）；命中判定=准星视觉中心 ±1 准星半径。
3. **延迟预算分段管理**：设备→游戏当帧→显示三段分别可测（`06` §4.3）；游戏侧目标=当帧判定（≤1 帧）；前摇/反应窗一律用绝对时间（毫秒）计时；内置延迟监视器（原始坐标/丢帧/输入更新率/延迟）。
4. **软校准而非强制校准**：信任设备端校准；30 秒快速软校准+实时追踪自检；一次保存，不再打扰（`06` §5）。
5. **映射失效自愈**：显示配置变化（分辨率/画幅/主副屏切换）会使绝对映射失效——游戏须能检测并引导重新校准，而不是放任玩家对着错位准星开枪。
6. **画幅切换不破坏判定盒**：安全区按实际画幅计算；强制拉伸画幅（如压成 4:3）会造成校准非 1:1（MAME 生态的 4:3 拉伸教训）。
7. **屏幕外坐标策略**：枪指屏幕外时钳边并冻结（不产生边缘扫射）；离屏装填优先接受设备注入的离屏事件而非从坐标推断（`06` §2.4）。
8. **后坐力友好事件**：开火/命中/受伤/装填四类独立信号广播+射速节流（`09` §3）——信号设计好，任何后坐力机构（电磁/气动/泵动；证据：Retro Shooter RS3 的全滑动电磁后坐力是社区口碑卖点）都能低成本接入。
9. **输入约定全兼容**：甩枪换弹（离屏装填，社区肌肉记忆）、踏板=节奏输入、侧键=方向/菜单——全部沿用+全键可重映射（`06` §1）。
10. **依赖检测与诊断**：屏幕追踪类设备可能依赖常驻解算软件——启动时检测设备与其依赖，缺失给引导页而非错误框；运行环境的输入中间层可能与外设软件冲突，提供诊断指引；内置光照自检（追踪状态实时显示+环境建议文案）。

## 3. 无枪降级是一等公民

铁律 3/4（`00` §2）：硬件会断代会缺席，而外设里藏着相当比例的体验，软件必须自己补齐。设计要求：

- **鼠标模式**：光枪位置流本就是绝对坐标，鼠标天然同构——完整体验，不是"暂时凑合"。
- **手柄模式**：右摇杆速度曲线独立调校（光枪玩家与手柄玩家的瞄准速度预期不同）+瞄准辅助选项。
- **软件侧补齐外设损失**：加重打击反馈栈（`09`）、降低对极限精度的要求（如减少人质类事件密度）。
- **无警告框**：检测不到枪时平滑进入降级模式，不弹"检测不到光枪"。
- **可检验指标**：无枪模式与枪模式的好评/留存对比（铁律 4 的检验式）。

反面证据：Silent Scope PS2 版（无光枪支持=玩法尽失）、Judge Dredd 家用版（"必须用真枪才有一点乐趣"）。详见 `06` §6。

## 4. 发布验收清单（通用版）

- [ ] 接上任何符合输入抽象契约的设备→启动→开枪即中，零配置零补丁
- [ ] 菜单全程可用枪操作
- [ ] 准星渲染开关（含街机模式）
- [ ] 当帧判定 + 延迟监视器
- [ ] 30 秒软校准 + 追踪自检 + 光照自检
- [ ] 多显示环境提供目标屏幕选择
- [ ] 双人开枪认领 + 热插拔 + P2 内容 100%
- [ ] 甩枪换弹/踏板/侧键约定兼容 + 全键重映射
- [ ] 后坐力事件信号文档公开（方便外设厂商对接）
- [ ] 无枪模式（鼠标/手柄）完整体验
- [ ] 判定盒覆盖自动化测试（四角+边缘+中心网格扫射）
- [ ] HUD 安全区预览
- [ ] 边界测试：四枪枚举（Point Blank 式 4P）、显示配置变化后自愈、显示器睡眠唤醒后追踪重连、无线设备干扰抽测

## 5. 反面案例账本（都是真差评）

| 案例 | 事故 | 教训 |
|---|---|---|
| HotD Remake（2022） | 光枪支持靠社区补丁才成立，Steam 刷屏 "LIGHTGUN SUPPORT PLEASE" | 原生支持必须是发布日状态 |
| Big Buck Hunter Arcade | 需第三方补丁且仅单人有效 | 双人完整性 |
| Operation Wolf Returns | 仅模拟指针输入且准星顶边够不着 | 全屏判定覆盖 |
| Until The Last Bullet | 枪打不到全部区域 | 判定盒覆盖测试 |
| Heavy Fire 系列 | 靠第三方工具脚本才完整 | 依赖第三方工具=不完整 |
| G'AIM'E | 傻瓜化封装值得学，游戏内准星抖动被 Reddit 警告帖 | 延迟与抖动是产品生死线 |
| Move 时代打包移植 | Razing Storm 三合一 MC58（IGN 4 分） | 旧内容打包+新外设=两头不讨好 |

**一句话总结本章**：光枪支持不是 feature，是**发布门槛**；设计活在输入抽象层上，硬件每一次换代，你的游戏就多活一代。
